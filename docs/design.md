# Architecture and methodology

Contract 3.0 is a four-layer design: canonical prose, typed state machine, strict schema/semantic validation, and optional immutable REST storage. The GPT supplies interpretation; code supplies identity, chronology, arithmetic and integrity only. Static/runtime/pipeline use identical gates. Pipeline projects a non-persuasive blind intake until Phase 2 is hashed and frozen.

Snapshot validity covers identity, session, corporate actions, price-source disagreement, currency and cutoff. Five signals remain independent. Event review precedes Phase-7 technical-zone locking. Value ranges never substitute for technical zones. Routes require full conjunctive conditions, unique priority, explicit exclusivity/transition and expiry. Allocation is target-position percentage, sums to 100 with waiting, caps each trigger at 40, respects pre-event limits and zeroes purchases for terminal gates.

Adversarial review precedes allocation. Simulation checks the canonical 14 paths for contradiction, duplicate consumption, stale zones and review requirements. Risk management distinguishes route failure, plan invalidation, thesis re-evaluation and integrity emergency; no forced percentage stop or order method exists.

Update Phase 2 evaluates immutable history; Phase 3 starts current analysis afresh; Phase 5 atomically supersedes. Outcomes are separately timestamped and remain `not_matured`; cutoff checks prevent future leakage. Publications use strict JSON, raw/canonical hashes, exact inventory, atomic rename and active-pointer verification. Failure leaves the prior generation active. See canonical contract for complete policy.
